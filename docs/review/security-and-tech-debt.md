## 二、技术债务

### T-1：证据充分性判断缺失（最高优先级）

**来源**：05-B / 05.5-A
**影响**：**高**

**问题**：

向量检索与混合检索**必然返回 Top-K**，即使语料里完全没有相关内容。

实测：查「安徽电力现货市场交易规则」（库中无安徽政策），Dense 与 Hybrid 均返回 10 条，
最高相似度 0.53。

**后果**：

- 4 条证据不足用例，Dense / Hybrid 均 **0/4 通过**
- 下游若直接使用检索结果，会把「最相似」误当成「有证据」

**当前处理**：

- `notice` 字段每次声明「相似度高低不代表证据充分」
- 评测中分别记录「候选召回」与「证据充分性」
- **不设相似度阈值**（4 条用例不足以标定）

**建议方向**：重排模型（cross-encoder）/ 阈值标定 / 二分类器。留待后续阶段。

### T-6：中文分词未引入

**来源**：05-A
**影响**：中

**问题**：

FTS5 trigram 按 3 字符滑窗切分，**少于 3 字符的查询无法匹配**，靠 `instr` 全表扫描回退。

- 「电价」「注册」「计量」等 2 字词只能走回退
- 回退是全表扫描，语料扩大后性能会退化

**当前缓解**：26 切片下回退 < 1ms。

**建议**：语料扩至千级后重新评估 jieba 或行业词典。

## 三、本次扫描的方法与局限

### 已执行的检查

| 检查项 | 方法 | 结果 |
|---|---|---|
| 密钥模式 | 正则：`sk-*` / `ghp_*` / `github_pat_*` / `AKIA*` / `PRIVATE KEY` | HEAD 未命中 |

| 历史敏感文件 | `git log --diff-filter=A --name-only` | 无高危文件 |

### 明确的局限

1. **模式匹配不等于完整审计**：无法识别非标准格式的密钥、经过编码的敏感数据、
   业务上敏感但无关键词的内容（如具体报价数字、客户名称）
2. **未做企业级合规审查**：无 DLP 工具、无人工逐文件审阅
3. **历史内容未逐个提交审阅**：仅做 `git log -p` 的模式扫描
4. **本次未扫描二进制文件内容**（PNG 截图可能含界面上的敏感信息，未做 OCR 检查）
5. **不构成「无泄露风险」的结论**

### 建议的补充措施

1. 仓库改为 Private 后仍应确认企业授权
2. 若转公开，必须先清理历史（或重建仓库）
3. 截图类文件建议人工复核是否含真实政策库数据
4. 建议接入 secret scanning 工具（如 gitleaks）作为 CI 门禁
