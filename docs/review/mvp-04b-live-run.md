## 四、真实运行中发现并修复的 3 个缺陷

### 缺陷 1：`CopywritingBudget` 上限与请求层不一致

`ContentWorkflowRequest.max_known_tokens` 允许到 400,000，
但 `CopywritingBudget` 只接受 ≤100,000。直接透传会抛 `ValidationError`
并让整个流程崩溃。

**修复**：传递时按各契约上限取小值（`min(...)`），并在注释中说明
「真正的约束是共享预算，阶段字段只是契约占位」。

### 缺陷 2：`ResearchBudget` 上限同样过严

同类问题：`ResearchBudget` 的 `max_api_attempts ≤ 30`、
`max_known_tokens ≤ 200000`。同样改为取小值。

### 缺陷 3：真实 LLM 网络异常导致流程崩溃

`CopywritingAgent.run` 只捕获 `CoreBudgetExceeded` 与 `CopywritingError`，
真实网络异常（`APIConnectionError`）会向上冒泡，让整个流程抛异常退出。

**修复**：增加通用 `except Exception`，转成 `ContentDraft(status=FAILED)`，
`status_reason` 写明异常类型。工作流据此返回 `final_status=failed`，
**优雅失败而非崩溃**。

### 缺陷 4：小标题被当作事实性陈述

真实模型生成的文案带「一、谁可以成为经营主体」「结语」这类结构标题。
审核把标题送去做语义核查，模型回答「证据中无此原文标题」，被判
`MACHINE_INSUFFICIENT`。这是**误判**：标题不含谓述内容，本不该核查。

**修复**：`_split_sentences` 先按行过滤标题（序号开头或固定的结构词如
「结语/总结/前言」），再按句号切分。测试 `TestHeadingNotTreatedAsFact`
覆盖 6 种标题格式与 2 种真实句子。

## 五、诚实记录的局限

| 项 | 说明 |
|---|---|
| **字数超出目标** | 实际 1042 字 vs 目标 800 字。真实 LLM 的字数控制是提示词级的，不精确。Mock 能精确控制是因为它做机械裁剪 |
| **网络不稳定** | 多次遇到 `APIConnectionError`（每次约 50 秒超时）。经代理后改善，但仍间歇性出现 |
| `usage_incomplete=True` | 因重试导致某次用量未知；这是软预算的如实标记 |
| 审核耗时 225 秒 | 真实 LLM 逐条判断语义支持性，成本较高 |
| 事实支持性是机器意见 | `fact_support_llm_used=True`，不代表专家确认 |
| **`final_status` 仍是 `pending_review`** | 即使四维全过、修订成功，也不表示可发布 |
