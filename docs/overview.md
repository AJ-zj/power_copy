# 项目概览

## 这是什么

PowerCopy V2 是面向**售电行业**的政策研究 + 文案生产 Agent 运行时。

它不是「一个能聊天的机器人」，而是一条从官方政策原文到可引用证据的**完整数据链路**——采集、解析、版本化、切片、检索、生成，每一环都可审计。

## 解决什么问题

售电业务的政策文案有个硬要求：**引用的政策必须是真的、当前有效的、能指给客户看的**。

纯 LLM 方案做不到这一点：

| 问题 | 纯 LLM | PowerCopy V2 |
|---|---|---|
| 政策原文从哪来 | 模型编造 | 官方域名白名单采集 |
| 政策是否最新 | 不知道 | 版本链 + 内容哈希 |
| 引用能不能溯源 | 不能 | 每个切片带精确字符区间 |
| 政策改了怎么办 | 不知道 | A→B→A 历史完整保留 |
| 是否适用安徽 | 可能胡说 | `notice` 明确声明边界 |

## 能力清单

### 已完成（阶段04 + 05.1）

**Agent 运行时**

- OpenAI 兼容 LLM 客户端，支持 Function Calling
- 三层预算控制：`RetryPolicy`（本地重试）→ `TaskBudget`（任务预算）→ `Agent` 循环
- `ExecutionTrace` 观测：模型调用、工具执行、预算消耗全程可查
- 消息管理：assistant / tool 消息回填，`tool_call_id` 严格匹配

**工具系统**

- 工具契约、注册表、执行器三层分离
- 参数用 Pydantic 严格校验
- 结构化错误：`TOOL_NOT_FOUND` / `INVALID_JSON` / `INVALID_ARGUMENTS` / `EXECUTION_ERROR`
- 真实政策工具：`search_policy`、`get_policy_detail`（只读 SQLite）

**数据中心**

- 数据源注册：3 个官方源，精确域名白名单
- HTTP 采集：禁代理、禁重定向、响应大小限制、错误分类
- HTML 解析：配置驱动 CSS Selector，零匹配/多匹配拒绝
- PDF 摄取：逐页提取、物理页码映射、审核指纹
- 版本化存储：身份/版本/观测三元组，双重哈希
- 只读查询：`mode=ro` + `PRAGMA query_only`，参数化 SQL

**RAG**

- 确定性切片：精确字符区间 `[start, end)`
- 自然边界优先：换行 > 句末标点 > 硬切
- `manifest_sha256` 保证可重复
- PDF 切片不跨物理页

**工作台**

- 后端：`workbench/data_api.py`（数据中心 API）+ `runtime_api.py`（Agent API）
- 前端：React 19 + Vite + TypeScript，10 个页面
- 全部对接真实数据，非 Mock

### 未实现（明确边界）

- OCR（扫描件、图片型 PDF）
- 向量数据库、BM25、混合检索
- 定时调度、增量索引
- robots.txt 自动检查
- 完整 SSRF 防护

详见 [技术边界](limitations.md)。

## 技术栈

| 层 | 技术 |
|---|---|
| 语言 | Python 3.12 |
| 数据校验 | Pydantic 2 |
| 存储 | SQLite（标准库 `sqlite3`） |
| HTTP | `urllib`（标准库） |
| HTML | BeautifulSoup 4 |
| PDF | pypdf 5.9 |
| API | FastAPI + uvicorn |
| 前端 | React 19 + Vite + TypeScript |
| 测试 | pytest |

**依赖克制**：采集用标准库 `urllib` 而非 requests，存储用标准库 `sqlite3` 而非 ORM，只有解析 HTML/PDF 引入了第三方库。

## 真实数据验证

当前库里有两份**真实官方政策**：

| 政策 | 来源 | 发布 | 正文 |
|---|---|---|---|
| 电力市场运行基本规则 | 国家发改委 | 2024-04-25 | 3829 字 |
| 电力市场注册基本规则 | 国家能源局 | 2024-09-13 | 6010 字 |

两份都完成了完整链路：采集 → 原始字节存档 → 解析 → 版本化入库 → 切片。所有哈希可逐项核对。
